# Marker

Клиент-серверная пара на .NET: сервер генерирует коды маркировки в формате GS1 и отправляет их по TCP, клиент принимает коды и дописывает их в файл.

## Требования

- [.NET SDK 10.0](https://dotnet.microsoft.com/download/dotnet/10.0)

## Структура решения

Решение находится в `src/Marker.slnx`.

| Проект | Назначение |
|---|---|
| `Marker.Common` | Протокол обмена (строки, разделённые `\n`), общий для клиента и сервера |
| `Marker.Server` | TCP-сервер и генератор кодов GS1 |
| `Marker.Server.Host` | Generic Host: конфигурация, логирование, запуск сервера |
| `Marker.Client` | TCP-клиент с переподключением и записью кодов в файл |
| `Marker.Client.Host` | Generic Host: конфигурация, логирование, запуск клиента |
| `Marker.Tests` | Модульные и интеграционные тесты |

## Сборка и тесты

Все команды выполняются из папки `src`:

```powershell
cd src
dotnet build Marker.slnx
dotnet test Marker.slnx
```

## Запуск

Нужны два терминала. Сначала запускается сервер, затем клиент (клиент можно запускать и раньше: он будет переподключаться, пока сервер не появится).

**Терминал 1 — сервер:**

```powershell
cd src
dotnet run --project Marker.Server.Host
```

Сервер слушает порт `5000` на всех интерфейсах и отправляет новый код каждому подключённому клиенту раз в 500 мс.

**Терминал 2 — клиент:**

```powershell
cd src
dotnet run --project Marker.Client.Host
```

Клиент подключается к `127.0.0.1:5000`, пишет в лог события подключения и дописывает полученные коды в файл `output/codes.txt` (по одному коду в строке). Путь относительный: при запуске через `dotnet run` он отсчитывается от папки проекта (`src/Marker.Client.Host/output/codes.txt`). Папка создаётся автоматически и добавлена в `.gitignore`. При повторном запуске новые коды добавляются в конец файла.

Остановка любого из приложений — `Ctrl+C`.

## Настройка

Хост-приложения построены на [Generic Host](https://learn.microsoft.com/dotnet/core/extensions/generic-host): настройки читаются из `appsettings.json` рядом с исполняемым файлом, логирование идёт через `Microsoft.Extensions.Logging`. Любой параметр можно переопределить переменной окружения (разделитель секций — `__`) или аргументом командной строки:

```powershell
$env:Client__Port = 6000
dotnet run --project Marker.Client.Host -- --Client:IdleTimeout 00:00:30
```

**Сервер** (`src/Marker.Server.Host/appsettings.json`, секция `Server`):

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `Address` | `0.0.0.0` | IP-адрес, на котором сервер принимает подключения |
| `Port` | `5000` | Порт |
| `GenerationDelay` | `00:00:00.500` | Интервал между отправляемыми кодами |

**Клиент** (`src/Marker.Client.Host/appsettings.json`, секции `Client` и `Output`):

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `Client:Host` | `127.0.0.1` | Адрес сервера |
| `Client:Port` | `5000` | Порт сервера |
| `Client:BufferCapacity` | `1000` | Размер очереди принятых кодов; при переполнении клиент ждёт потребителя, коды не теряются |
| `Client:IdleTimeout` | `00:00:10` | Сколько ждать очередной код, прежде чем считать соединение мёртвым и переподключиться. Не задан — ждать бесконечно. Должен быть заметно больше `GenerationDelay` сервера |
| `Client:Resilience:InitialDelay` | `00:00:01` | Пауза перед первой попыткой переподключения |
| `Client:Resilience:MaxDelay` | `00:00:30` | Максимальная пауза между попытками |
| `Client:Resilience:Multiplier` | `2` | Во сколько раз растёт пауза после каждой неудачи |
| `Client:Resilience:MaxAttempts` | `null` | Максимум попыток переподключения; `null` — без ограничений |
| `Output:Path` | `output/codes.txt` | Файл, в который дописываются принятые коды |

## Протокол

Каждый код передаётся одной строкой UTF-8, завершённой символом `\n`. При чтении допускается `\r\n`, пустые строки игнорируются.

Клиент защищён от повреждённых данных:

- **Склеивание и фрагментация.** Несколько кодов в одном пакете разбираются по отдельности, код, разрезанный между пакетами, собирается целиком.
- **Слишком длинная строка.** Если строка превышает 1024 байта (`LineMarkingCodeFormat.DefaultMaxLineBytes`), чтение прерывается с `InvalidDataException`.
- **Обрыв посреди сообщения.** Если соединение закрылось, а последний код не завершён `\n`, он отбрасывается с `InvalidDataException`, а не принимается как валидный.
- **Молчащий сервер.** См. `IdleTimeout` выше.

Во всех этих случаях клиент сообщает причину в событии `Disconnected` и переподключается по настройкам `Resilience`.
